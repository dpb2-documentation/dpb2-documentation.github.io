Introduction

Getting Started

Set up the toolchain, scaffold a project from the official template, and build your first DPB2 plugin into a deployable DLL.

How plugins work

DPB2 does not compile plugins from source, source-loading is not planned. You compile a .dll yourself and drop it into the bot's Plugins folder. On launch, DPB scans those DLLs and instantiates every type that implements IBase (so any IBot, IRoutine, IPlugin, IPlayerMover or IContent).

Folder name must match the DLL

The plugin must live at Plugins\<Name>\<Name>.dll, the folder name has to match the DLL name exactly, or DPB will not load it.

Prerequisites

  • A working DPB2 installation (this guide references v0.4.5.x).
  • The .NET 8 SDK, required to build net8.0-windows assemblies.
  • An IDE: Visual Studio 2022, JetBrains Rider, or VS Code with the C# Dev Kit.
  • Windows. The bot is a WPF desktop application.

Install the .NET 8 SDK

The quickest route on Windows is winget:

winget install Microsoft.DotNet.SDK.8

Verify it is available. If dotnet is not on PATH for a fresh shell, call it with the full path:

# typical install location
& "C:\Program Files\dotnet\dotnet.exe" --version
Pather server prerequisite

If the pathfinding ("pather") server fails to start, install both x86 and x64 .NET Core 8.0.8+ runtimes. Also disable any High DPI override on the DPB executable, because Windows display scaling causes missclicks and broken navigation.

Point your project at the DLL

Plugins reference DreamPoeBot.dll from your DPB install. The cleanest approach is an environment variable that your .csproj reads, so the path is not hard-coded:

# set a user environment variable (run once, then restart your shell/IDE)
setx DPB2 "E:\DPB2 v04301\DPB2"

Your project then resolves references through $(DPB2):

<ItemGroup>
  <Reference Include="DreamPoeBot">
    <HintPath>$(DPB2)\DreamPoeBot.dll</HintPath>
    <Private>false</Private>
  </Reference>
</ItemGroup>

<Private>false</Private> prevents the bot's own DLLs from being copied into your output, you only want to ship your assembly.

Use the official template

There is an official dotnet new template that scaffolds a correct project (references to DreamPoeBot, log4net, MahApps.Metro and Newtonsoft.Json; net8.0-windows with UseWPF + UseWindowsForms enabled):

github.com/Letale-vc/DPB2Plugintemplate

Install the template, then create a new plugin project from it. The csproj includes a CopyToPlugins flag that automatically copies the built DLL into $(DPB2)\Plugins\<ProjectName> after each build, so a build is also a deploy.

# install the template package, then scaffold a project
dotnet new install Letale-vc.DPB2Plugintemplate
dotnet new dpb2plugin -n MyFirstPlugin

Build & deploy

Build in Release. With CopyToPlugins enabled, the DLL lands in the right folder automatically:

dotnet build -c Release

Without the auto-copy flag, deploy manually, remember the folder/DLL name rule:

E:\DPB2 v04301\DPB2\Plugins\
└── MyFirstPlugin\
    └── MyFirstPlugin.dll   ← folder name == dll name

  1. Close DPB2 before deploying

    DPB loads plugins on startup and writes settings on exit. Replacing a DLL while it is running can fail or load a stale copy. Build → close DPB → confirm the DLL copied → relaunch.

  2. Select your plugin in the UI

    An IBot appears in the bot dropdown, an IRoutine in the routine dropdown, and an IPlayerMover in the mover dropdown. A plain IPlugin is enabled in the plugins list.

  3. Check the log

    The DPB log window reports load errors, exceptions and your own Log.* output. It is your primary debugging tool, most problems show up here first.

Settings live in JSON

Some DPB2 builds expose no settings tab in the window. In that case, tune your plugin by editing its JSON directly at Settings\<config>\<Name>Settings.json (default config is Default) while DPB is closed. See Settings & UI.

Enable IntelliSense docs

Keep DreamPoeBot.xml next to the referenced DreamPoeBot.dll in your install folder. Your IDE will then surface the framework's XML documentation (Coroutines, Pathfinding, ObjectManager…) as IntelliSense tooltips.

The XML only documents helpers

DreamPoeBot.xml documents the framework helpers well, but not entity property members, those exist only in the DLL metadata. To discover them, use the reflection dumper.
