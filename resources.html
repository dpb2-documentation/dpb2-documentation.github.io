Mind the version gap

Reference projects may target a different DPB2 build than yours. A newer bot can reference APIs your build lacks (e.g. ExpeditionUi), and an older one can use members since removed. If a reference doesn't compile against your DLL, repoint its HintPath and reconcile the handful of changed members rather than assuming it's broken.

Performance tips

  • Enable the input hook once, not per loop. It's the difference between a ~200 ms and a ~1000 ms main loop.
  • Avoid chained LINQ (especially OrderBy) over large object sets. Pull once, cache by type, skip processed ids, do one action per cycle.
  • Use a stopwatch CPU-limiter when scanning objects on big maps.
  • Keep Message() handlers cheap; they run on the main coroutine thread.

Operational tips

  • Keep DreamPoeBot.xml beside DreamPoeBot.dll for IntelliSense docs.
  • If the pather server fails, install both x86 and x64 .NET Core 8.0.8+ runtimes.
  • Disable High-DPI override on the DPB executable; Windows scaling breaks clicks and navigation.
  • Profiles: each folder under Settings\ (besides Global) is a config profile. Rename one with DPB closed to rename the profile.
  • Edit settings JSON only while DPB is closed, it loads on start and overwrites on exit.
