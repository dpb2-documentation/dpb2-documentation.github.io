API Discovery

The bundled XML documents framework helpers, but not entity property members. To discover those, inspect the DLL metadata directly with a reflection dumper.

Why you need this

DreamPoeBot.xml documents the framework helpers (Coroutines, Pathfinding, ObjectManager) well, but the property members of game entities, what's actually on a Monster, Item, AtlasNode or a UI panel, exist only in the compiled DLL metadata. The reliable way to find them is to enumerate the type's members via reflection.

Use MetadataLoadContext, don't run the DLL

MetadataLoadContext loads an assembly purely for inspection. It never executes any code, so you can safely enumerate DreamPoeBot.dll without launching the bot or attaching to the game. This is what makes a standalone dumper tool possible.

The approach

  1. Create a small console project targeting net8.0.
  2. Add the NuGet package System.Reflection.MetadataLoadContext.
  3. Point a MetadataLoadContext at DreamPoeBot.dll (plus the .NET runtime assemblies as resolver paths).
  4. Resolve a type by name and print its public/instance members.

A minimal dumper

using System.Reflection;

// Resolve assemblies from the DPB folder + the .NET runtime directory.
var dpb = Environment.GetEnvironmentVariable("DPB2")
          ?? @"E:\DPB2 v04301\DPB2";
var runtime = Path.GetDirectoryName(typeof(object).Assembly.Location)!;

var paths = Directory.GetFiles(dpb, "*.dll")
    .Concat(Directory.GetFiles(runtime, "*.dll"))
    .Distinct();

var resolver = new PathAssemblyResolver(paths);
using var mlc = new MetadataLoadContext(resolver);

var asm = mlc.LoadFromAssemblyPath(Path.Combine(dpb, "DreamPoeBot.dll"));

foreach (var typeName in args)              // e.g. "Monster" "AtlasNode"
{
    var type = asm.GetTypes()
        .FirstOrDefault(t => t.Name == typeName || t.FullName == typeName);
    if (type == null) { Console.WriteLine($"!! {typeName} not found"); continue; }

    Console.WriteLine($"\n=== {type.FullName} : {type.BaseType?.Name} ===");

    const BindingFlags F = BindingFlags.Public | BindingFlags.Instance
                         | BindingFlags.Static | BindingFlags.DeclaredOnly;

    foreach (var p in type.GetProperties(F))
        Console.WriteLine($"  prop  {p.PropertyType.Name,-22} {p.Name}");
    foreach (var m in type.GetMethods(F).Where(m => !m.IsSpecialName))
        Console.WriteLine($"  meth  {m.ReturnType.Name,-22} {m.Name}(" +
            string.Join(", ", m.GetParameters()
                .Select(x => $"{x.ParameterType.Name} {x.Name}")) + ")");
}

Usage

Dump one or more types by name, or a whole namespace:

# dump specific types
dotnet run -- Monster Item AtlasNode

# dump everything in a namespace (extend the tool to accept --ns)
dotnet run -- --ns DreamPoeBot.Loki.Game.Objects
Handy extra flags

Worthwhile additions: --ns <Namespace> to list every type in a namespace, and an --impl <Interface> mode to find which types implement an interface (useful to confirm, for example, that no built-in IBot/IRoutine/IPlayerMover ships inside the core DLL).

Walk the base types

Because DeclaredOnly shows only members declared on the type itself, walk up BaseType to see inherited members too. That's how you discover that a Monster's Health/HealthPercent actually come from Actor, and Position/Metadata from NetworkObject.

for (var t = type; t != null && t.Name != "Object"; t = t.BaseType)
{
    Console.WriteLine($"--- declared on {t.Name} ---");
    // …print t.GetProperties(DeclaredOnly) as above
}

A practical workflow

  1. See a type you don't understand in IntelliSense

    You get a Monster back from GetObjectsByType but don't know what's on it.

  2. Dump it

    dotnet run -- Monster prints every property and method, including the base-class chain.

  3. Confirm namespaces & signatures

    The dump shows exact return types and parameter lists, so you call UseOn / FastMove / FindPath with the right arguments the first time.

  4. Verify before relying on it in-game

    Metadata tells you a member exists; it doesn't guarantee the value is live. Some fields are stale or static (see Patterns & Gotchas). Log and confirm.
