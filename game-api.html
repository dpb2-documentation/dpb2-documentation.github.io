Reference

Game API

The core of DPB2: reading the world through LokiPoe, the entity hierarchy, pathfinding, sending input and skills, and driving the in-game UI.

Namespaces

Most of the API lives under DreamPoeBot.Loki.*. Notable exceptions: Vector2i is in DreamPoeBot.Common (not Loki.Common); Skill is in DreamPoeBot.Loki.RemoteMemoryObjects; Rarity is in DreamPoeBot.Loki.Game.GameData; and Keys is just System.Windows.Forms.Keys.

LokiPoe, the gateway

LokiPoe is the static entry point to all game state and input. The members you reach for constantly:

ObjectManager, reading the world

Query loaded entities by type. The most common call:

// every alive, hostile, targetable monster within range
var monsters = LokiPoe.ObjectManager
    .GetObjectsByType<Monster>()
    .Where(m => m.IsAliveHostile && m.IsTargetable
             && m.Distance <= combatRange);

// other lookups
var device  = LokiPoe.ObjectManager.GetObjectByName<NetworkObject>("...");
var byId    = LokiPoe.ObjectManager.GetObjectById<WorldItem>(id);
var chests  = LokiPoe.ObjectManager.GetObjectsByType<Chest>();
var items   = LokiPoe.ObjectManager.GetObjectsByType<WorldItem>();
Performance: LINQ is expensive on big maps

The ObjectManager is a snapshot dictionary of id → address; every property access reads from memory. Chaining Where/OrderBy over large object sets is slow, OrderBy especially. Pull objects once per tick, cache the props you need, and skip already-processed ids (object Id is unique per zone). Do one action per cycle and return.

The entity hierarchy

World entities form an inheritance chain. The base members exist everywhere; the richer ones appear as you go down the tree.

NetworkObject

Base for everything in the world. Name, Position (Vector2i), Distance, Id, Metadata, Reaction, IsHostile, IsTargetable, Components, Entity (an EntityWrapper with .Address).

Actor : NetworkObject

Anything alive. Health, MaxHealth, HealthPercent, Mana, IsDead, HasBuff, HasAura(string), GetStat(...), GetSkill(...), CannotDie, Invincible, HasProximityShield. Action state: CurrentAction (an ActionWrapper with Skill / Target / Destination), HasCurrentAction, IsUsingAbility, IsTargetingMe, TimeSinceLastAction.

Player : Actor  →  LocalPlayer : Player

LocalPlayer (= LokiPoe.Me) adds IsInTown, IsInHideout, EquippedItems, TownPortal, Auras.

Monster : Actor

Rarity, Level, IsAliveHostile, IsMapBoss, Tags. Use IsMapBoss to identify the real boss, not every Rarity == Unique monster (roaming unique exiles are not the map boss).

InstanceInfo.MinimapIcons is a list of MinimapIconWrapper (ObjectId, MinimapIcon.Name, LastSeenPosition). The icon name identifies content generically, e.g. "Strongbox", "Essence", "Ritual", "Delirium", "AbyssPitActive", "Rare"/"Unique"/"Boss". This avoids guessing metadata strings for every mechanic.

Pathfinding, ExilePather

ExilePather is the navmesh. The core call returns a PathResult struct (in …Pathfinding.RDWrapper.Types) with .Success and .Path (a List<Vector2i>):

// start, end, useWaypoints, hops
PathResult path = ExilePather.FindPath(
    LokiPoe.Me.Position, target, true, 5);

if (path.Success)
{
    foreach (var wp in path.Path) { /* walk toward wp */ }
}
Reload the pather once per area

Before any pathing or explorer use in a new area you must call ExilePather.Reload(true) (synchronous) once, or you get "Cannot use PathExistsBetween before Reload is called." Guard it on a saved AreaHash and gate the rest of your logic on ExilePather.IsReady. Do not await the async reload from inside a coroutine.

Other useful ExilePather members:

MemberUse

GridExplorer

The built-in IExplorer tracks discovered tiles and hands you the next place to go:

var explorer = new GridExplorer { AutoResetOnAreaChange = true };
explorer.Start();
// each tick (gated on ExilePather.IsReady):
explorer.Tick();
if (explorer.HasLocation)
    PlayerMoverManager.MoveTowards(explorer.Location);
double pct = explorer.PercentComplete;
explorer.Ignore(badLocation);   // give up on a point you can't reach

Movement

Movement goes through PlayerMoverManager.Current.MoveTowards(Vector2i, ...), which calls into the selected IPlayerMover. A mover implements:

public interface IPlayerMover // (+ IBase, IAuthored, etc.)
{
    PathResult? CurrentCommand { get; }
    bool MoveTowards(Vector2i destination, params object[] args);
}

Click-to-move requires the Move skill bound on the skill bar (LokiPoe.InGameState.SkillBarHud.LastBoundMoveSkill). PoE2 also supports WASD movement (LokiPoe.Input.CurrentInputMethod == InputMethod.WASD), which frees the mouse to aim, useful for ranged kiting, but it requires the game itself to be set to the WASD control scheme.

Input & skills

Enable the hook first

Call LokiPoe.ProcessHookManager.Enable() once in Start(), or UseAt/UseOn return ProcessHookManagerNotEnabled. Call it once, repeatedly enabling it balloons the main loop to ~800–1000 ms; once-only keeps it ~200 ms.

Use a skill via the skill bar (SkillBarHud). Results are a UseResult enum where None means success:

var bar = LokiPoe.InGameState.SkillBarHud;

// cast at a target object
bar.UseOn(slot, /*inPlace*/ false, monster, /*clearKeys*/ true);

// cast at a world position
bar.UseAt(slot, false, point, true);

// HELD / continuous fire: BeginUseAt with clearKeys = false, and do NOT
// call ClearAllKeyStates between shots, that breaks channeling/held-fire.
bar.BeginUseAt(slot, /*inPlace*/ true, point, /*clearKeys*/ false);

// find a skill by its bound mouse button, then read its slot
var left = bar.Skills.FirstOrDefault(s => s.BoundKey == Keys.LButton);
int slot = left.Slot;

Lower-level input through LokiPoe.Input:

CallUse
SimulateKeyEvent(Keys.Space, true, false, true, Keys.None)Tap a key (down + up), e.g. a dodge roll. Press = (down:true, up:false); release = (down:false, up:true).
MoveMouseToWorldPos("…", point)Aim the mouse at a world position (keeps a held move-key going).
ClickLMB / ClickRMBMouse clicks.
ProcessHookManager.ClearAllKeyStates()Release all held keys. Use it before a dodge, never between held-fire shots.
Humanize timings

Use LokiPoe.Random.Next(min, max) (good seeded RNG) for delays. Generate a value, store it, and regenerate it after the action, not every tick.

Items & loot

Ground loot is WorldItem; inventory/stash entries are Item. Interact via the framework coroutine Coroutines.InteractWith(worldItem, false) (awaitable directly).

var loot = LokiPoe.ObjectManager.GetObjectsByType<WorldItem>()
    .Where(w => w.HasVisibleHighlightLabel   // passes the in-game item filter
             && w.IsTargetable
             && w.Distance <= lootRange);

Item exposes rich data: Name, Class, Metadata, Rarity, StackCount, LocalId, ItemLevel, Quality, affixes (ExplicitAffixes / ImplicitAffixes, each a ModAffix with InternalName, IsPrefix, Values…), and defensive/weapon stats (ArmorValue, MaxDps, …).

Guard every item property read

Item.Name, Item.Class and Item.Rarity can throw "BaseItemType not found" for some ground items, and HasVisibleHighlightLabel can throw NullReferenceException. Wrap all item reads in try/catch, an unguarded read inside a LINQ Where crashes the whole task.

UI panels

UI panels hang off LokiPoe.InGameState and are mostly static classes, so you access their members directly and can't instantiate them.

Stash

var stash = LokiPoe.InGameState.StashUi;          // also GuildStashUi
bool open = stash.IsOpened;
var names = stash.TabControl.TabNames;            // List<string>
stash.TabControl.SwitchToTabMouse("CURRENCY");    // returns None on SUCCESS
var ctrl  = stash.InventoryControl;               // current tab grid
// move an item between inventory and the open stash tab:
ctrl.FastMove(item.LocalId, /*actuallyMove*/ true, /*ignoreIncubators*/ false);
Re-fetch wrappers; special tabs differ

Don't cache an InventoryControlWrapper; re-fetch it each operation (the framework no longer updates a held reference). Special-typed tabs (Currency / Map / Fragment) return a null InventoryControl and need their dedicated reader classes (CurrencyTab, FragmentTab). Generic tabs have a real InventoryControl you can read and withdraw from. Wrap stash reads/switches in try/catch, since empty normal tabs throw on read.

Atlas & map device

PoE2 endgame is the Atlas. Interact the map device object, then drive AtlasUi (static):

var atlas = LokiPoe.InGameState.AtlasUi;
if (atlas.IsOpened)
{
    var node = atlas.UsableAtlasNodes
        .First(n => !n.IsCompleted && n.CanBeUsed);
    atlas.MoveToNode(node, 5000);
    atlas.OpenNodeInventory(node);

    var dev = LokiPoe.InGameState.AtlasUi.AtlasMapDeviceUi;
    dev.Waystone_InventoryControl... // place a waystone via FastMove
    dev.Traverse();                  // creates the map portal, then enter it
}

Newer builds (0.4.5.16+) made AtlasNode reliable and added AtlasUi.AtlasEndgameContentIcons / AtlasIslandsNodes / AtlasTowerNodes, each node has Coordinate, FullTooltip, Click(), IsInFOV(pct) and MoveTo(timeout).

A map run runs at the waystone's tier

AtlasNode.MinWaystoneTierRequired is the node's minimum accepted waystone tier, not the resulting map tier. The map runs at the tier of the waystone you place. Filter nodes by MinWaystoneTierRequired > 0 && <= yourWaystoneTier, not by a high minimum.

Vendor & dialog

NPC interaction goes through NpcDialogUi (static): CanConverse, Converse, BuyorSellItems(), Goodbye(). In PoE2, selling is done by FastMove-ing the item to the open vendor window, which credits gold directly.

When in doubt, dump it

The DLL metadata is the source of truth for entity and UI members. The reflection dumper lists the exact members of any DPB type without executing the assembly, the fastest way to discover undocumented properties.
